# 6주차 요청 발생기

슬라이더로 요청량을 바꾸고 Kubernetes의 API Pod 수 변화를 관찰합니다. 이 저장소는 **요청을 보내는 앱**이며 Docker Compose로 실행합니다. **요청을 받는 Kubernetes·Minikube 프로젝트**는 별도 [week6_practice](https://github.com/Mok2Lee/week6_practice) 저장소입니다.

## 1. 수신 프로젝트 먼저 실행

`week6_practice`의 실습 안내에 따라 Kubernetes 앱을 실행하고 웹 서비스를 PC의 **8080 포트**에 연결합니다. 연결한 PowerShell 창은 열어 둡니다. <http://localhost:8080>에서 대시보드가 열리는지 확인합니다.

## 2. 요청 발생기 실행

교수자가 접근 권한을 제공한 `week6_sender`를 본인 계정으로 Fork합니다. 새 PowerShell 창에서 본인 저장소를 내려받습니다. 아래 `본인아이디`를 바꾸세요. 수신 실습에서 이미 복제했다면 `week6_sender` 폴더로 이동해 Compose 실행부터 진행합니다.

```powershell
git clone https://github.com/본인아이디/week6_sender.git week6_sender
Set-Location .\week6_sender
docker compose up -d --build
```

`week6_sender` 폴더의 `compose.yaml`을 사용합니다. Python 설치나 가상환경 설정은 필요하지 않습니다.

<http://localhost:8090>에서 **프로젝트 검색** 또는 **소개글 분량 검사**를 선택하고 **요청 시작**을 누릅니다. 두 화면을 함께 보면서 아래 순서로 슬라이더를 바꿉니다.

| 요청량 설정 | 관찰 시간 | HPA 기준이 Pod당 50건/분일 때 이론적 Pod 수 |
| --- | --- | --- |
| 40건/분 | 90초 이상 | 1개 |
| 120건/분 | 90초 이상 | 3개 |
| 220건/분 | 90초 이상 | 5개 |
| 요청 중지 | 최근 60초 요청 수가 줄고 축소될 때까지 | 최소 1개 |

각 단계에서 **실제 성공한 요청 수**, **Pod 수**, **응답 Pod 이름**을 확인합니다. 표는 실제 성공 요청량이 설정값에 도달했을 때의 예상값입니다. 최근 60초 집계와 Pod 준비에 시간이 걸리므로 결과가 안정되지 않으면 더 기다립니다.

## 3. 과제: 요청량과 HPA 기준 비교

1. 기본 기준 **50건/분**으로 40 → 120 → 220건/분을 보내고 실제 요청량과 Pod 수를 기록합니다.
2. `week6_practice`에서 HPA 기준을 **50 → 75건/분**으로 바꿉니다. 수정 위치와 적용 명령은 수신 저장소의 과제 안내를 따릅니다.
3. 같은 **220건/분**을 유지하며 변경 전후 Pod 수를 비교합니다. 75건 기준의 이론적 Pod 수는 3개입니다.
4. **요청 중지**를 누른 뒤 최소 1개로 줄어드는 과정을 확인합니다.

HPA 기준은 **수신 저장소에서 수정**합니다. 이 요청 발생기에서는 슬라이더로 요청량을 조절합니다. 발생기의 8090 포트와 수신 대시보드의 8080 포트를 구분하세요.

## 종료와 연결 확인

먼저 화면의 **요청 중지**를 누르고 `week6_sender` 폴더에서 실행합니다.

```powershell
docker compose down
```

연결 실패가 나오면 수신 앱의 실행 상태와 8080 포트 연결을 확인합니다. 발생기는 `http://host.docker.internal:8080`으로 요청을 보냅니다. 슬라이더 최대값은 250건/분이며, 이미 보내는 중인 요청 1건은 중지 후 완료될 수 있습니다.
